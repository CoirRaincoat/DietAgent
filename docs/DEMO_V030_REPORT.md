# Demo v0.3.0 交付报告

项目：方太个性化膳食规划 Agent · ZX-2026-0301
日期：2026-09-24 · 阶段：Phase 10

## 1. 新增功能

- 独立 Vue 3 + Vite + TypeScript 前端，Axios 调用既有 API；后端保留 app/，不为目录命名搬迁稳定业务。
- 自由对话、历史消息、合成画像选择、新对话、真实等待与错误重试。
- 人数、餐次、忌口等澄清按后端结构显示可点击选项；未知过敏等开放问题由用户具体回答。
- 菜品卡片、主要食材、原始用量与步骤、菜谱来源行/ID/指纹；原生详情对话框支持键盘关闭。
- 按位置换菜并标记发生变化的卡片；其余菜单由后端状态保持。候选建议只读查看，不声称能强制选择建议 ID。
- 本餐营养来源卡片、健康目标匹配、食材贡献、依据链接、风险和局限。热量及营养摄入量均明确数据不足。
- `/demo` 三个实际交互案例：减脂晚餐、不要鱼换菜、不能吃辣；每个案例使用新的合成用户会话。
- Docker Compose 分离部署，根路径提供用户界面，`/api/` 同源代理到内部后端；原 API 调试和验收路径保留。

后端业务变化仅为版本元数据 0.3.0，响应 schema_version 保持 2.0。没有修改 Agent、规则、检索、规划或营养计算逻辑，也没有删除原测试。

## 2. UI 设计说明

使用暖白底色、深绿主色、鼠尾草绿和少量暖橙强调。桌面布局为画像侧栏、对话区、菜单/营养区；窄屏上下排列。桌面会话区域保持可见，首屏压缩空白以便直接发送消息。

菜品采用自绘抽象餐盘占位，并标注“菜品示意 · 非实拍”；没有外部图片、虚构菜品照片或精确营养图。当前只有单餐数据，所以面板使用“本餐营养”，不包装成全天摄入。没有可计算总量，不画雷达分数、达标进度或克数。

状态只来自实际后端：未澄清不显示有效菜单；模型请求过程中显示等待；工具执行名称来自返回的 tool_calls。网络失败后隐藏有效菜单，保留原请求供重试；同一会话串行，重试使用相同 payload/request_id。新对话、切换画像和演示案例清空旧会话及未发送草稿。

独立审查修正了两处演示边界：移除可能覆盖已确认人数的固定补齐按钮；只有本轮响应为 ok 才显示演示操作完成，过敏澄清和无可行菜单均不标完成。

桌面与 390px 手机截图存于被忽略的 `artifacts/screenshots/`。Mock 截图中的菜名明确是合成测试内容，只用于页面验收。

## 3. 三分钟演示流程

打开 `http://localhost:8080/demo`：

1. 点击“减脂晚餐”，在对话中逐项回答人数与忌口，展示主动澄清和已确认条件。
2. 菜单生成后打开一道菜的详情，展示原始食材、步骤及数据来源。
3. 点击第二道菜的“换一道”，查看该位置更新；点击营养页签，展示来源、风险和数据不足。
4. 切换“灵活换菜”新案例，明确整餐排除鱼并重新规划；或选择“记住忌口”，追加“不能吃辣”，展示新的限制与实际响应。

可直接在首页自由对话。默认 900001 为日常用餐合成画像，900002 带合成海鲜/花生过敏与控糖偏好，900003 带合成清淡偏好及健康目标。所有画像均与真实个人无关，真实资料不进入在线联调。

## 5. 启动与停止

项目根目录，Docker 引擎已运行且本地 `.env` 已配置：

```powershell
.\.venv\Scripts\python.exe -m evaluation.demo_start
```

启动器现默认复用已有镜像且不拉取；首次部署或更新代码后请加 `--build` 显式构建，`--no-build` 仍兼容。页面地址：

- 用户界面：`http://localhost:8080`
- 演示模式：`http://localhost:8080/demo`
- API 文档：`http://localhost:8080/docs`

```powershell
docker compose --env-file configs/compose.env stop
```

命名卷保留数据，重新执行启动器即可恢复服务。启动器用 Settings 解析现有 dotenv，不修改原 `.env`；Compose 显式使用空 `configs/compose.env`，密钥仅通过子进程环境传给后端，不进入前端构建或命令参数。

本地开发：先在根目录用 Uvicorn 启动 8000 后端，再在 frontend/ 执行 `npm ci` 和 `npm run dev`，访问 5173；Vite `/api` 自动代理后端。Node 22.12+，本机验证版本 24.14.1。完整命令见 [README](../README.md)。

## 7. 当前边界与 Phase 11

仍是无鉴权、本机访问、单 worker 的共享单餐 Demo。未实现逐人份量、多日计划、营养精确计算、指定候选 ID 替换、完整撤销约束或页面刷新后的历史会话恢复。当前限制不会用模拟值掩盖。

真实菜单有多道鱼菜时，“不要鱼，换一种”会触发替换范围澄清，界面正确清空有效菜单且不标完成。内置演示动作因此明确为整餐排除鱼并重排，保留现有人数和餐次；单道换菜继续使用卡片槽位按钮。

实际联调发现“最近想减肥”可能解析为未支持目标“减肥”，未归一到现有“减脂”。保留失败报告，并将内置手写演示句明确为“最近想减脂，帮我安排晚餐”，没有修改后端核心，也没有把此问题记成理解成功。自由输入同义词的支持边界仍需独立评测。

下一阶段按 Phase 11 组织独立合成 NLU 评测：缺字段、否定、过敏词歧义、多轮修改和失败恢复；将模型意图准确率与规则/状态正确率分开统计，再整理三分钟比赛讲稿、证据截图和能力边界。此次没有提前扩展后端业务或宣称完成 Phase 11。
