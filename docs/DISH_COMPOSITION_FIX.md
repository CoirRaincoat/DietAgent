# 明确荤素数量：执行、独立验收与人工复核

2026-10-01，本地分支 `fix-menu-intent-continuation`。代码提交：`c60fd53`（酸梅饮品反例）、`ec3d9c0`（数量执行）、`019be82`（独立验收）。没有推送或合并。

## 这轮实现了什么

“共7道，其中2道汤、2荤3素”现在有独立原文数量解析、Intent/会话字段、规划执行、最终核对和强制解释事实。总菜数仍含汤；荤素数针对非汤、非主食的成菜。未指定数量保持 `null`，0不是未指定。范围、冲突、模型凭空添加的数量先澄清，未解决状态在继续/重启后保留。

明确口径：素菜允许蛋奶，不等于纯素。肉末、肉汤、猪油、蚝油等源证据会使非汤菜计荤，即使它的主要成菜角色是蔬菜；蛋白质来源角色与荤菜身份分开。不明高汤、鸡粉和未覆盖复合食材不凭“没看见肉”认证素菜。植物同名“羊肚菌”“贝贝南瓜”不会被字面动物字误判；混合真实肉/贝原料仍保留动物证据。

数量选择在已通过硬筛选的候选中进行：四个互斥组的剩余容量前瞻避免先选菜后无位可填。尽量按槽位保留可行旧菜；指定换菜时保护其他位置，冲突需确认整餐调整，不偷偷扩大范围。已满足后的重试不换菜。食材偏好修补、角色修补、替换建议和HTTP/SSE解释均不得破坏明确数量。数量占满非汤菜位时，不强塞一道主食挤掉荤素要求。

本次没有引入通用求解器依赖；这是互斥数量组的有界可行性处理，不保证全局偏好最优、全局最少修改或任意多人质量最优。

## 独立验收

`evaluation/composition_oracle.py` 读取开发者逐条审核源原料/步骤后编写的菜谱ID类别表，**不导入生产分类器、不接受服务自报数量或文案作为真值**。主菜单及每个第一槽替换建议都核对；缺少审核记录不能默认算素菜。需要同时启用源真实性、唯一ID、总数/汤数与正餐资格检查，数量审核表不能替代这些门禁。

公开验证器升v12，数量oracle为v1；源正餐反例oracle升v6，整餐角色目标升v2。既有开发数据集v3字节不变，历史报告不改写。本次新增源反例：宫廷酸梅汤有乌梅/冰糖/过滤冷藏饮品证据，不能填正餐汤位；“酸梅汤炖排骨”不因饮品子串误拒绝。
