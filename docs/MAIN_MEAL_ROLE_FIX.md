# 正餐资格修复与人工复核（2026-10-01）

代码提交：`8b5940f`。本轮只修正餐成菜资格，不等于完成多人荤素结构、健康目标或回复质量优化。

## 已实现与边界

- `app/domain/meal_roles.py` 统一主菜单、换菜建议、HTTP/SSE 和旧菜单解释的正餐资格。重新核对名称、配料与做法；陈旧 vegetable 元数据不能绕过。饮料、甜点、加工步骤和无已识别正餐角色记录不默认填位，无足够可用菜品时如实返回无解/澄清。
- 饮料里的胡萝卜、蛋糕里的鸡蛋不再使该记录承担蔬菜/蛋白质/主食成菜角色。区分甜汤和咸汤，甜梨汤少量盐不被误认为咸汤。不按“水”“汁”“糕”子串一刀切，盐水鸭、茄汁白玉菇、萝卜糕和非甜米糕有对照测试。
- `synthetic-validator-v7` 新增独立 `main_meal_eligibility` 检查菜单与建议；不导入生产分类器，不相信返回类别或安全标志。命中角色反例的菜单不产生质量观察值。公开 v3 文件字节不变，新旧验证器分别报告。
- 这些规则和独立核验都是有限启发式/反例集合，不证明所有菜谱适配、份量或营养。没有引入下午茶甜点/饮料规划模式；甜味标签本身不是甜点判据。
