## 机制与边界

- 普通菜单路径排除源名称/标签/步骤明确的宝宝辅食、婴儿专用或“给宝宝食用”准备；名称含宝宝本身不足以拒绝，否定表述及明确全家可食用不误作专用。规则用于主菜单、建议与旧菜单解释。没有实现婴幼儿专餐、年龄/疾病适配，不推断未知成员年龄。
- 餐次仅使用确切源标签。原文有标签时，不相信过时的 `meal_types` 缓存，不把提及“早餐/晚餐”的解释段落或JSON字符串当标签。明确匹配、未知、仅其他餐次三级软排序；先保工程角色，再比较餐次，随后健康/检索/本餐多样性。
- 旧菜单先做既有角色/食材偏好修复，再有界同角色交换，每次降低餐次代价。保持主角色、汤位、显式荤素数量、已覆盖食材偏好、唯一菜谱及指定槽位；满足后重试不反复交换。并非全局最少修改或最优求解器。
- 无标签或仍有其他餐次菜时，提示进入强制解释事实；极简模型说明、SSE和旧菜单解释不能隐藏。标签不是禁食、临床适配、份量或营养达标证明，不因缺标签虚报无解。
- 建议不引入宝宝专用源记录，不降低第一槽已知餐次证据。硬过敏/不辣/整餐素食仍由原有门禁执行，餐次分数不能豁免。
- 独立验证器 v14 支持 `expect.meal_context`，读取另行逐条审核的源 ID/人群/标签，不导入生产分类器。严格模式对缺失、其他餐次、婴儿专用和未审核 ID 均失败；非严格只核普通人群，不能宣称餐次已验证。失败阻止质量观察；源真实性仍需另过门禁。

## 新暴露问题与下一阶段

- 椰子玛格丽特：糖粉/黄油/低筋面粉小面团烘烤，仍被旧分类当蛋白质成菜。
- 山药酸奶盆栽：等量山药/奥利奥加酸奶的甜点，候选建议仍进入主食替换。
- 固元阿胶糕：阿胶、冰糖、核桃等冷却切块，不是普通肉菜，候选建议仍出现。
- 木瓜炖银耳：冰糖45g的甜羹，候选建议仍占蔬菜角色。
- 红豆薏米粥：唯一源步骤仅红糖混合2分钟，未交代豆谷煮熟；不能凭“取出食用”认定配方步骤完整。
