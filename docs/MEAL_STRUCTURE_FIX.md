# 多人整餐角色目标与有界修复

2026-10-01，本地提交 `046297c`（源证据补强）、`6854e70`（整餐结构）。尚未推送；算法长任务仍在进行。

## 改动与边界

角色目标现在使用实际人数、餐次和非汤菜位，不再把五人晚餐与单人菜单一律设成一道蛋白质菜。至少三人的午/晚餐且有至少五个非汤菜位时，工程默认目标为至少两道蛋白质来源菜、两道蔬菜类菜、一道主食。其他菜单按可用菜位缩小目标；早餐不套用这个两道蛋白质菜规则。显式菜数、汤数仍优先，不因默认目标擅自加菜。

这是可解释的工程默认，不是膳食指南、明确荤素要求或五人摄入量计算。豆腐也可以占蛋白质菜位；蔬菜主角色不表示纯素。早餐细致适餐和用户指定“几荤几素”尚未实现，不能将它们计作已满足。

菜单先经过原硬约束与资格门禁，再保留合法旧槽位、覆盖食材偏好，最后在缺少角色时进行有界单调交换。每次交换提高已满足的角色数量，不丢失已覆盖角色和食材偏好，不移动汤位；同等改善时优先复用已变化槽位，再使用原健康/偏好分和检索顺序。目标已满足的重试不继续换菜。

指定“只换某一道”会阻止额外全餐修复。目录不足、已覆盖食材偏好或局部换菜范围导致的角色缺口会进入警告与不可省略的解释事实。它不保证任意输入下全局最优或最少修改，也不把无法补齐的软目标误报为硬约束失败。

入口：`app/agent/meal_structure.py`；规划、搭配观察、建议和回复通过 `planner.py`、`menu_balance.py`、`suggestions.py`、`response_copy.py` 与 `service.py` 衔接。版本为 `contextual-meal-roles-v1`。

## 回放暴露的源数据问题

只增加角色数量时，源目录仍选出了甘蔗马蹄水、黑芝麻糕、仅准备步骤的汽锅鸡；后续又发现荔枝饮品、肉桂甜点、未烹饪虾滑和没有米证据的卤肉饭。全部中间菜单保留，没有用最后的绿灯覆盖这些失败。

- 有限植物同名词不再提供动物来源证据：马蹄、果肉、肉桂等；混合配方仍保留真正的肉、虾等原料。不修改原始配方，也不是过敏或素食全量判定。
- 明确饮品、甜糕、加工中间物和只有洗切准备的记录不能承担正餐菜位；完整烹饪的同名变体仍可通过。未知步骤不因没有负面词就被证明完整。
- 饭/面形态必须有粮食原料证据；缺米的肉饭不被降格解释为第二道蛋白质菜。补充粳米、挂面、高筋粉等有限别名，蛋饺、肉饼和菜卷不凭名称强行算谷物主食。
- 原始 ID、来源行、指纹、原料与步骤均保留。角色规则升为 `primary-culinary-role-v2`；独立有限反例验收为 `main-meal-counterexample-oracle-v5`、公共验证器为 `synthetic-validator-v11`。公开 v3 数据集字节不变，旧报告不改写。

当前 2000 条源记录中，16 条标记准备-only、29 条加工记录；仍有 87 条 eligible 未知角色（上一阶段94，一度因别名缺失增加到154）。这不是全库准确率或完整召回率，需要后续独立人工审核。
