# 不辣硬约束修复与测试记录（2026-10-01）

## 范围

只修“不辣”的执行及独立验收，不改多人搭配、健康排序、跨餐去重或营养计算。生产规则增加小米辣、油泼辣子、辣子油、糍粑辣子和明确的辣椒面证据；对辣、微辣、香辣、酸辣标签保守拒绝。原配方有可选辣味配料也拒绝，不能擅自删除配料后把新做法冒充原菜谱。

成分不明复合配料、食材解析不完整时不声称满足不辣；没有不辣限制的行为不受这项检查影响。没有任何可用菜时返回 no_feasible_menu，不输出违规菜凑数。黑胡椒、白胡椒、甜椒、彩椒不因“椒”字被一律封禁；“不辣”等标签不因含“辣”字而误判。检查只覆盖有限词汇和源证据，不保证品牌配方或个人辣味感受。

独立验收位于 evaluation/no_spicy_oracle.py，不导入生产规则/词表；公开回归使用预期约束、预期用餐者或用例显式不辣检查触发，源标签和可见标签只能提供拒绝证据，不能证明无辣。私有矩阵的本地源验收同时更新，未访问私有档案。验证器升级为 synthetic-validator-v6，v3 测试集字节不变。

## 源菜谱检查与历史复核

离线读取真实源菜谱，仅使用合成条件，无外部模型请求。两个历史菜单中的川北凉粉、酸辣藕带都被拒绝，替换后无关槽位不变（2/2）。但替换出的山楂糕、蓝莓山药小丸子仍暴露下一项正餐资格缺陷，旧菜单中的果蔬汁也继续保留；本次通过只证明不辣筛选，不是整餐合格。

重新审核两版已保存的合成模型输出：82 个成功菜单轮次中 7 轮食材检查失败（基线 4、候选 3），包括主菜单配料以及替换建议的辣味标签。它是离线重新验收，不是重新运行模型，也不是所有 98 轮对话的总通过率；原始报告和 AI 判断未覆盖。

## 复测命令

在项目目录、工作正常的测试 Python 环境中运行：

```powershell
python -m pytest tests/test_no_spicy_acceptance.py -q -p no:cacheprovider --basetemp ./runtime/pytest-non-spicy-check --junitxml ./runtime/non-spicy-check.xml
python -m pytest -q -p no:cacheprovider --basetemp ./runtime/pytest-full-check --junitxml ./runtime/full-check.xml
```

Windows 若使用 basetemp，先确保 runtime 父目录存在；使用当前项目的解释器，不在桌面目录执行相对 tests 路径。下一项先修正餐菜位资格，再调整多人结构，继续保持一主题一个变更。
