## 本轮实现

- 同会话存最近 8 份推荐菜单的源名字／ID／餐次，另记新餐序号。只表示推荐过，不推断吃过、日期或实际摄入。
- 仅有限首句肯定新餐命令＋规划动作允许开始另一餐，例如“安排下一餐，沿用原要求”“安排明天晚餐”；问句、否定、引用、假设及解释／局部换菜不扩大范围。
- 试验新餐清旧菜位及单餐拒绝，保已知过敏、不辣、人数、饮食模式、明确数量／方法和未知安全问题；未核对旧做法／口味选项不跨新餐沿用。
- 最后同等适配候选中优先减少最近同名菜暴露：角色、餐次、做法、规则、检索和同餐相似度先固定；逐目标不退步，源已有偏好食材／方法／类别参考保留，注意项不新增。
- 普通继续、同请求重放、解释、局部换菜不记成新餐；SQLite 状态重启后保留，跨用户会话 409。

构造函数 `experiment_cross_meal_rotation=False`，API／模型／环境无打开入口。离线测试只在本地直接设置试验；不是默认生产接入。
