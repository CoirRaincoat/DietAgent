# feat: 执行明确荤素数量并独立核对菜单与换菜建议

## 背景

已有蛋白质/蔬菜主角色不能执行“三荤两素”，含肉末的蔠菜也不能按主角色宣称素菜。这轮将原文数量、会话、候选选择、解释和独立验收接通，不把数量正确冒充整体推荐质量。

## 改动

- 新增非汤、非主食成菜的荤素数量字段及有限原文解析；0与未指定区分，冲突/范围/模型猜测数量先澄清，重启与继续保留待确认状态。
- 荤菜来源与主角色分开；允许蛋奶的素菜需有限正向源证据，不明高汤/复合配料不默认算素菜。补羊肚菌/贝贝南瓜植物同名边界。
- 在安全候选内做互斥类别容量前瞻，保留可行旧槽位、重试稳定和单槽替换范围；后续偏好/角色修补及换菜建议不能破坏数量。
- HTTP/SSE强制输出经核对的数量及口径；纯素只澄清，不假装已实现纯素推荐。
- 独立验收用开发者源审核表，不读取生产分类器或自报标签；验证器v12、数量oracle v1。源回放发现酸梅饮品占汤位，新增独立反例oracle v6；旧v3数据与报告保留。
- 导出测试集、逐项结果、五份源前后菜单、中间失败与待办，更新创新点草稿。

## 验证

- 252项专项、1171项全量通过，1条既有TestClient警告；192种数量组合与独立穷举对照。
- 数量模块语句98.80%、分支97.37%；源分类/独立验收100%；严格mypy、Black、Ruff通过。
- 同输入/CSV五组离线回放：基线明确数量均不满足，候选均满足该有限口径；原始贝贝南瓜/酸梅汤失败菜单保留。
- 本地人工复核包有源码、菜谱/输入哈希、逐例结果、原料步骤及五次规划计时；详见 `docs/DISH_COMPOSITION_FIX.md`。

## 边界及后续

荤素口径仅限非汤、非主食，素菜允许蛋奶。**0荤示例仍有猪骨汤，不是整餐素食。** 整餐素食、成人/餐次适配、健康目标、肉类主菜充足、跨餐重复仍待完成。皮冻、含少量肉片白菜的荤菜身份不证明优质蛋白或五人份量。未覆盖复合调料可能损失素菜召回，有限源证据不是纯素或过敏安全认证。

本次未调用生成模型/AI Judge，未填人工标签，TTFT/端到端性能未测，不给质量总分。容量前瞻不是全局质量求解器，不保证全局最少修改。报告/私有数据/密钥仅本地保存；只本地提交，不自动推送或合并。
