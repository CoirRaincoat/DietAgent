# 标题

fix: 按有限源步骤识别成汤，修复汤位漏算与高汤固体菜误分类

## 背景与实际修复

去重联动诊断发现，源591“南瓜海鲜盅”被归为蔬菜，但原步骤明确将熟南瓜打汁入高汤，再在汤中加海鲜等煮开、煮沸食用。旧版会把它与另一道汤一起放进“含1汤”的菜单，或对“含2汤”错误报告候选不足。

生产实现提交 `a55f6ed947ad52d83cdca4c0407c13a80018bfae`、`7203dc6a1c3ca09c89a1c96017576736f736fbcc`：

- 新增有限成汤证据：汤中加料加热、结束食用，且有同子句食物泥汁基底或明确连汤盛入碗/盅。高汤、水、器皿名、设备、煮开或蒜泥单独不足。
- 捞出/沥干、收汁、后续固体成菜阻断补汤；主食/蛋类和非正餐/加工组件原优先规则保留。
- `高汤炒/烧/焖/煎…`不因名字含汤误归汤。
- 正餐资格复核源证据与派生汤角色一致，缓存假蔬菜/蛋白/主食角色不进入规划与换菜建议。过敏、不辣等原硬门禁不放宽。

## 同输入实际规划器证据

28项旧版 `b30dbd1` 与新版 `7203dc6` 的实际 MenuPlanner 对照，候选ID/次序和请求不变，每路重复两次稳定；基线来自已校验的旧独立快照报告，新版重新运行。

|---|---|---|
| 3菜含1汤 | 海鲜盅＋蒸鸡肉＋番茄豆腐汤，源依据实际2汤 | 西兰花＋蒸鸡肉＋海鲜盅，1汤 |
