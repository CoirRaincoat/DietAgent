# fix: 按人数与汤位修复整餐角色，保护局部换菜边界

## 背景

人工抽查发现五人晚餐被饮料、甜汤占位，且合法旧菜单缺少主菜时不调整。之前正餐资格和主要成菜角色修复仍不能证明整桌结构合适。本次补上下文角色目标，并保留真实失败和未满足项供人工复核。

## 改动

- 角色默认考虑人数、午/晚餐和非汤菜位；五个非汤菜位的多人正餐默认两道蛋白质来源菜、两道蔬菜类菜、一道主食，不改变用户明确数量。
- 在已硬筛选候选内单调修复缺口，保留汤位、已覆盖偏好；已满足重试不换菜，指定局部换菜不额外调整整桌。
- 候选不足或换菜边界限制时保留角色缺口，作为不可省略的解释事实，不用成功状态掩盖。
- 补源证据反例：甘蔗马蹄水、荔枝饮品、甜糕、仅准备步骤、未完成虾滑；植物同名词不冒充肉类来源；主食形态需粮食证据，并补有限别名及蛋饺/肉饼边界。
- 保留源菜谱ID和原始配方；角色v2、独立反例oracle v5、验证器v11，开发数据集v3不变。

## 边界与后续

蛋白质菜不等于肉菜或摄入克数；蔬菜角色不等于纯素，默认结构不是明确“几荤几素”。早餐、人群、健康目标、跨餐重复仍需后续主题。剩余87条eligible未知角色需要审核，有限反例门禁不是全库准确率。规划交换不保证全局最优或任意输入最少修改。
