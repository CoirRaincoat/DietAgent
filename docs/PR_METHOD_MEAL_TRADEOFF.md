# 确认餐次与明确做法的有界取舍，并续接原任务

## 背景

前轮独立DeepSeek意见指出：保护并披露“晚餐与蒸制参考冲突”仍不足，应让用户选择取舍。本轮实现确认流程，不以默认评分替用户决定，也不把有界搜索未找到共同候选说成全库无解。

## 实现

- 有限餐次改善方案丢失明确做法覆盖时询问：优先餐次参考、优先明确做法参考、暂不规划。若已有同覆盖联合候选，优先核对餐次成本，避免假取舍。
- 选择来自明确原文，不能由模型填枚举代选。问题式、假设式和普通“继续”不代选；暂停保留问题而不执行。
- 保存完整需求/目录源与派生字段绑定、原菜单及plan/replace/reject范围；明确选择后续接原任务，重启和请求ID重放保持，源或需求变化使旧许可失效，新换菜不继承旧范围。
- 双方案保留过敏、不辣、其他覆盖、明确多样性、数量及单槽编辑边界；餐次优先不是取消做法记录，更不是解除所有偏好。
- 已确认优先项及尚缺参考成为必选事实，不能被可选解释模型省略。旧SessionState新增字段有默认值；新增解析上下文仅动作/槽位/三个选项，不发送新增源提示、备选ID或绑定哈希。
