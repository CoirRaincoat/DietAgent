## 实现

- 原始口味标签和有限菜名参考命中酸/甜/蒜香等排除时不放行；缓存标签、蒜的弱配料线索不证明味觉。有限复合参考有向判断：“不要酸”排酸甜，“不要酸甜”不误排纯酸。奶香不推甜、清淡不推低钠。
- 有授权规划/换菜/整单拒绝时，有限无归属负向原文补充到状态，避免模型漏提后仍推荐糖醋菜；问题/引用/假设/归属/解除语句不作为此补充路径授权。
- 严格“不辣/不要辣”补独立硬字段并核对配料，川北凉粉没有辣标签也不能因辣椒放行；不太辣不自动等同零辣。新硬字段不重复成未知软偏好。
- 指定槽位之外已有负向来源冲突时要求整餐调整许可，不默改其他菜。明确正负口味冲突改为clarification_required，保留两项、等待确认，不输出成功菜单；当前通用解除闭环仍未实现。
- 选菜后必选事实逐菜披露“未见明确排除参考，实际味觉无法核验”，最小解释模型不能隐去。负向“不要清淡”不再获得正向蒸/煮定性加分。
- 保留不辣/过敏、数量、旧菜单状态、局部范围、请求ID重放、重启及普通继续，不修改源Recipe模型、身份或原2000条。
