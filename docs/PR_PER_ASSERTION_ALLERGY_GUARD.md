# 部分过敏信息遗漏：逐句归属核对与安全续接

## 范围与实现

基线 `4312553`，本地代码 `9b80e3e`；未推送、合并或部署。旧守卫只要在任意位置看到已解析过敏字段就跳过全文，导致“爸爸花生过敏，妈妈有食物过敏”只解析出爸爸时直接排菜。

新增 `uncovered_allergy_mentions` 对每个有限原文声明及其主体分别核对本轮提取。已知爸爸的信息不能替代妈妈未知项，部分食材列表或并列主体也不能只覆盖一半。完整的无过敏声明与有证据的既有要求引用仍保留；“不辣且虾过敏”“不辣、虾过敏”中的不辣条件由独立硬约束路径处理，不误当过敏食材。

识别明确关系称呼、既有名字／别名和有限同主体前缀；未被可靠核对的信息保存为待确认，不补猜过敏食材。明确不参餐者的未知项保留但不阻断当前餐，之后加入时再阻断；未能可靠归属的部分仍作为会话级未知，不凭新标签消除。已知食材、不辣、身份、重启、重放、跨用户隔离、局部菜位和旧菜单无效状态继续保护。

DeepSeek 适配器把规划改为防漏澄清时，保留内部 `_allergy_guard_plan` 来源标记，以免原本请求的餐丢失。它是私有属性，不进 JSON schema、模型输出、请求或持久化；模型试图通过 JSON 设置它会失败。保存的是原有解析操作，不授予新操作权限：解释不是规划授权，局部换菜因新未知被阻断后不扩成整餐重排。两个模拟 HTTP 提供商测试跨真实适配器和服务核对防漏、恢复及完整提取路径，没有付费调用。

守卫不是通用中文／共指理解、商业配料安全认证或完整过敏信息校准。短代词桥接只接受此前明确命名的唯一活跃提取主体与完全相同食材；多主体、无可靠名字或缺字段保留待确认。更广复杂引用／否定、规范化别名、复合配料和真实模型表现仍需验证。未改变原菜谱、标签、健康功效或份量。

实际工作流显示：部分提取时先返回澄清、对应人的未知项与原待规划保留；明确后恢复三道餐，同时保留其他人的已知过敏及不辣。没有以空菜单充当正常推荐，也没有删除未知信息刷绿。旧成功菜单遇到新未知先失效，解释／局部换菜不输出旧菜单冒充已经校验。缺字段的名单成员、既有别名、缺一部分食材列表、不参餐后加入及重放／跨用户均保存具体响应。
