# fix: 区分成菜主角色与食材来源，修复菜单类别虚假覆盖

## 改动

- 源菜谱按一个主要成菜角色归一化，鸡肉玉米肠不再同时覆盖蛋白质菜、蔠菜及主食；排骨汤只占汤位，蛋炒饭和饺子只占主食位。
- 保留原料、步骤、稳定 ID、来源行与指纹；含肉末的蔠菜仍保留肉末营养来源，不称为纯素，也不推算蛋白质克数或份量。
- 明确调味品和动物同名蘑菇不能当蛋白质来源；补源数据“米”的精确别名，未知保持未知。
- 菜单质量观察升为 `source-menu-diversity-v2`，旧 v1 多标签观察不可直接横比，历史报告保留。
- 输出本地人工复核包，包括输入、逐项结果、源菜单对照与需求状态，更新算法 TODO 和创新点草稿。

## 验证

- 手写开发集 30 组，专项 55 项通过；原测试在旧代码上 15 失败，回放发现米别名后又复现 2 项失败，均保存。
- 全量 815 项通过，1 条既有 TestClient 弃用警告。
- 新模块语句/分支覆盖率 100%；严格 mypy、Black、Ruff 通过。
- 同 CSV、同合成约束的 3 份前后离线回放已保存，本地复核入口见 `docs/PRIMARY_DISH_ROLE_FIX.md`。

## 边界与后续

- 本 PR 只修已知角色虚假覆盖，不代表全部分类、多人荤素搭配或份量已达标。仍有 94 条 eligible 无角色记录待审核。
- 分类来自有限菜名/食材/步骤启发式，不代表纯素、低钠或健康疗效。
- 未重新调用真实模型或 AI Judge，未重测 TTFT/端到端性能，开发通过率不是官方或人工质量评分。
- 下一步修多人整餐目标与有限调整，并保持不辣、过敏、局部换菜和重试稳定。
- 私有数据、密钥、未脱敏报告不提交；仅本地提交，推送和合并由用户执行。
