# 正文

## 目标

让明确场景需求影响真实菜单，而不止保存标签。详细做法只用于原有来源判断，不扩写2000条原文；验收看菜单与缺口，不看新增标签数。

## 改动

- 有限明确场景子句补充到已有preferences；更新意图提示，不从人数/职业/年龄/健康目标反推场景。提问、解释、引用或假设不触发这条原文补充链路。
- 原场景标签/明确菜名参考参与检索排序；可选required_scenes只筛同时有指定源参考的候选，无命中不回退。默认规划仍保留未知场景菜谱，不将软参考升级为安全保证。
- 追加场景后的逐槽有界修复，保护硬约束、同角色、明确荤素数、餐次、逐健康目标、已覆盖食材/口味与已知成菜方法；只换指定菜和空继续保持范围。
- 后续口味修复及替换建议保护该槽的已覆盖场景；缺标、未知、负向与冲突逐项进入必选回复事实，一道菜有参考不声称整餐适配。

## 边界与未完事项

- 场景源信息稀疏；未知不等于不适合。现有家常、一人食、节日参考不是人数份量、携带/保存安全、耗时或健康功效标签。
- 一般负向场景完整筛选、冲突解除/澄清仍待实现，当前明确披露且不给被冲突排除的旧正向偏好加分。
- 有界交换不是全局组合最优或无解证明。旧10份菜单未改善，同质化、商业/装饰配料、跨餐/检索/组合和独立留出原TODO仍保留。
- 无新真实模型、外部Judge、独立助手或人工质量评审；AI/人工/质量分为null，模板事实不是模型输出。离线工程耗时不证明模型首token通过，有些场景增加开销。
- 本轮仅本地提交，不自动推送、创建远程PR或合并。
