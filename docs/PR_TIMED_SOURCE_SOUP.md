# 修复明确无汤菜单的定时煲汤漏判

## 问题与实际变化

默认路径在公开两人午餐4菜0汤案例中，把源方明确执行定时煲汤的菜当作非汤角色，并允许未核实去汤的火锅进入无汤菜单。旧公开自动检查没有发现这个实际问题。

同输入修后两类菜退出，生成四道来源可追溯的原库菜单。完整原料、步骤和回复只在本地人工报告，不随本PR上传：`runtime/zero_soup_live_fix_20261005/human-review/report.md`。

## 实现与边界

- 源成菜共同判断识别明确时间＋煲汤程序，不依赖名称以汤或煲结尾；更新角色证据版本。
- 原配方后续真正沥汤、收汁或固体完成优先；引用、否定及可选程序不算执行，谷物／蒸蛋形态与非正餐组件保持既有边界。
- 含汤底且最终煮炖、无去汤依据的火锅不能保证0汤，仅限制无汤资格，不自动重标成1汤或推算成品比例。
- 原2000CSV、意图Prompt、求解／排序、候选池、付费开关与API格式均未改；过敏、不辣、纯素、明确数量和局部权限不放宽。
