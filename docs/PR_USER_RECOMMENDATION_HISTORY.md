## 本轮实现

- SQLite 按实际 `user_id` 读最近 8 份推荐，跨会话而非固定选择一位用户；查询可排除当前会话／餐序，只含源菜名、ID 和餐次，不转移旧会话过敏、用餐者或健康档案。
- `(session_id, meal_sequence)` 唯一收据：局部换菜更新本餐记录不新增一餐，相同完成／解释／重放不再次计账；编辑旧餐不把它重新排成最新餐。
- 最后已返回的推荐快照与餐序持久化，拒绝／规划失败不抹掉它；另起一餐可继续使用已推荐历史。只表示推荐过，不表示吃过。
- 缓存回复、会话快照、推荐收据及用户历史版本在短事务中提交；收据必须等于实际成功返回菜单。失败、错菜名／ID、无效菜单不入历史。缓存插入或历史版本冲突使整个完成事务回滚，原先保存的澄清／限制阶段仍遵循既有合同。
- 完成写入校验 `user_id`，不能更换另一个用户会话的归属。同进程按用户串行化，不同用户不共锁；跨实例通过历史版本比较拒绝旧历史上的轮换提交。版本为存储私有属性，不入模型 JSON／schema。
- 默认 OFF 不读／写轮换历史，也不会因为库里已有试验历史自动启用；初始化只增加空历史表和默认状态字段，没有回填旧档案或旧对话。

这仍是以请求的 `user_id` 为命名空间的 Demo，不等于新增登录认证或私有部署授权。
