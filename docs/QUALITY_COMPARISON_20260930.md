## 失败记录不覆盖

原历史对照 PR10 29/30、PR11 28/30 的理解失败报告继续保留。本次公共修复后首轮又出现基线 29/30、候选 30/30：基线 `basic_explicit_peanut_allergy` 收到 HTTP 503 / `LLM_UNAVAILABLE`；单独诊断回放两次模型请求均为 200，未复现，具体服务故障原因不能确定。之后只完整重跑基线一次，通过 30/30，候选复用同条件已通过的完整报告；没有删除失败场景或拼接单轮补测结果。这不证明模型服务长期稳定。

裁判最初以 1800 Token 上限运行，交换顺序请求未通过校验；一次有安全元数据的诊断回放确认 `finish_reason=length`、正式文本为空、1798 个 completion Token 均为思考 Token。现在支持 `JUDGE_MAX_TOKENS` / `--max-tokens`，仍严格拒绝截断或无效 JSON。本批改用 8192，重新评审，不混入 1800 批次判断；量表与全部 60 份交换顺序输入已经核对，内容不变。一次顺序运行中的在途请求被中断，是否计费未知；已有效返回的判断在同配置下续跑，最多 3 个场景并发，每场景内部先 A/B 再 B/A。

反例与待核对方向：

- `basic_single_complete`：基线第 3 项为“茄汁白玉菇”，候选为“果蔬汁”；前两项相同。裁判认为饮品充当晚餐“3 道菜”中的一道，正餐角色较弱。`basic_profile_health_goals` 与若干追加限制场景也出现类似差异。
- `interaction_local_replacement`：两版都只换第 2 道为“山楂糕”，局部修改边界守住；但候选保留果蔬汁，最终甜品/饮品角色重复。仅核对菜位与源菜谱，不足以评价菜单搭配。
- `interaction_replace_third_dish`：候选胜。基线换入“爽口凉皮”，与保留的“川北凉粉”角色相近；候选换入“卤香菇”，搭配相对更互补。这说明多样性机制并非所有场景都无用，不应仅凭总胜数直接全盘否定。
- `interaction_profile_allergy_explanation`：平局不代表优质。两版都仅重复“已避开海鲜、花生”，未按用户要求逐菜说明；裁判还指出两版共有的正餐角色问题。需要关注两版同样较差的场景。

上述为可复核的模型评语，不是营养或医疗结论；做法、餐次及类别上的疑问仍应回到源菜谱核对。下一项算法方向先候选为**菜品角色与餐次适配、加工食材规范化及解释事实对齐**，人工核对后再决定具体改动；暂不优先增加 MMR 或组合求解器复杂度，不擅自撤回已合并 PR11。

人工标签尚未填写，人机一致率、Cohen's κ 和人工校准结论均为未测。应由未看过 AI 结论和解盲映射的评审员完成至少 20–30 组盲评，最好填写全部 30 组；无明显差异可平局，无法判断留空。不能让本裁判代填人工标签。

## 人工抽查与离线核对（2026-10-01）

用户抽查反馈：单人晚餐重复推荐、不辣仍推荐川北凉粉、健康目标匹配不可信、五人晚餐饮料甜汤过多。只做读取与离线诊断，未调用外部 API、未改算法、未代填人工 CSV。

- 原盲评 `review-007` 第 2 轮明确“不吃辣”，两版仍含川北凉粉；源配料与步骤都有“油泼辣子”，当前规则以 `Constraints(no_spicy=True)` 核对仍允许。`review-003` 明确小李不吃辣，两版仍含酸辣藕带，源配料与步骤均含“小米辣”，同样被允许。源辣味标签分别含“辣”，当前不辣检查只查有限配料词，不使用这些标签。
- `configs/rules.yaml` 与 `evaluation/cases/regression_v3.json` 不辣词表均漏“小米辣”“油泼辣子”。独立验收虽不调用生产 RuleEngine，词汇覆盖仍有共同盲区。因此 30/30、硬约束全过不是无辣证明，不更改旧报告数字，但撤回其作为完整硬约束保证的解读。既有 AI 结论仅为旧输入及旧量表下的偏好证据，不代替安全验收。
- `review-019` A/B 菜单完全相同：鸡肉玉米肠、蚕豆炒韭菜、茄汁白玉菇、果蔬汁、黄瓜柠檬水、绿豆汤。源配料证实前者有鸡胸肉，后二饮品含蜂蜜/糖粉，绿豆汤含冰糖。当前分类遗漏两个 drink，将饮品当 vegetable；甜汤未与正餐咸汤区分。`_is_main_meal` 依赖这些标签，未能拦住。
- `balance_rank` 的角色目标只按总菜数设置，蛋白质类别目标始终最多 1，并惩罚超过该目标的蛋白质菜；没有按人数或餐次调整。主食、蔬菜等标签允许一菜多计，不等于满足相应份量。鸡肉玉米肠因“玉米”被标 staple，亦需核对成菜角色与实际主料，不能据此证明主食充足。
- 当前降压为带调味品扣分的软排序，护心未配置规则；规则返回“暂未配置定性排序规则”。这不能支持“降压护心已满足”，也不能凭凉粉菜名断言医学禁忌；应核对真实配方、排序和解释边界。
- 当前菜单多样性只在本餐同等适配候选间比较；同约束主菜单仍确定性选取，没有跨餐历史去重。仅可选替换建议具有 session 轮换。重复一部分来自固定选取，一部分可能是有限适配候选，需要后续分层重复率测量，不能靠盲目随机化解决。

下一步先补不辣生产检查及独立人工反例验收，再处理正餐资格和多人结构，最后评价健康解释与跨餐多样性。人工抽查是定性缺陷证据，不是已完成至少 20 组的人工盲评/校准；标签和 κ 仍待填写、计算。
