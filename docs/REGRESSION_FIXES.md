# 食材筛查与多轮状态回归修复

本次修复针对公开 v0.3.0 审查中可复现的三类业务错误。没有修改原始菜谱、真实资料使用边界或营养能力声明。

## 食材归属筛查

原先猪肉、鸡肉等限制依赖少量同义词，遗漏猪小排、鸡翅和牛肉部位；小麦词表遗漏吐司等。新增可选 `food_families`，将食材归属与库存同义词分开，避免把鸡胸肉库存当作鸡翅库存。

肉类部位和派生食材只从配料及步骤匹配，菜名不是食材证据。配置明确排除鸡腿菇、牛肝菌、牛油果等同形词；相关肉类限制下，鸡精、泛称肉丸等来源不明的配料保守拦截，理由标为不确定，而非断言必然含某类肉。这类未知来源不计入偏好覆盖。词典仍有限，不代表完整品牌配方或医学交叉反应判断。

真实菜库回归覆盖：

| 限制 | 原漏检菜品 | 原始食材证据 |
|---|---|---|
| 猪肉 | 排骨焖饭 | 猪小排500克 |
| 鸡肉 | 鸡翅包饭 | 鸡翅3个 |
| 小麦 | 番茄金枪鱼芝士吐司挞 | 吐司2片 |
| 牛肉 | 测试按稳定ID读取的牛排配方 | 牛排1块 |

每个案例同时验证过敏和明确忌口，以及旧菜单在新增限制后必须替换。反例测试还覆盖其他肉源、名称相似植物、步骤新增食材和严格库存。

## 连续否定

原先仅排除上一轮菜单，连续两次否定可能出现 A → B → A。现在明确整份否定累加到 `SessionState.rejected_recipe_ids`，在规划前持久化；后续规划和候选建议排除累计菜品及同名变体。规划失败后的解释不会复活已拒菜单。

普通单道替换不产生永久拒绝；新会话不继承旧会话记录。字段默认空列表，兼容旧SQLite会话JSON与缓存响应，无需修改数据库表。

## 食材偏好

原先仍通过硬筛选的旧菜占满槽位，追加牛肉偏好只更新状态，菜单完全不动。现在对整餐计算食材偏好覆盖，在通过硬筛选的候选中尝试局部交换，每次严格增加覆盖并保留已覆盖偏好。

优先选择一次覆盖更多缺失偏好的菜，在覆盖收益相同时优先复用已改槽位、保留菜品类别。指定局部替换不扩大软修改范围；无法安全覆盖的偏好返回提示，保留可行菜单。同一约束重复规划不会持续换菜。

这是有界局部启发式，**不保证全局最少修改**。仅健康排序目标变化仍不会重排既有菜单；完整约束撤销、历史方案恢复、逐人营养与正式评测接入不在本次范围。

同时处理缩减菜数与替换位置矛盾：指定位置超过新总菜数时返回明确失败，避免数组越界。
