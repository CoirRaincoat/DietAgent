# 同餐食材家族去重实验：暂不接纳

2026-10-01，代码提交 `11a07c4ac10a1f9c80a076b96d17571a4ba6d996`。长任务仍在进行；只作本地提交，未推送或合并。这个阶段是候选算法试验，不是已上线的质量优化。

## 原因与实现

旧精确食材重叠把南瓜、贝贝南瓜、熟南瓜块分开；健康修复只接受目标严格增益，不能执行等适配去重。本次增加独立于过敏/营养归一化的有限食材家族表，只读已声明食材，不从菜名补证据，不把酱、油、鸡粉或未知当成新颖食材。它不判断主料占比或个人摄入量。

`repair_menu_variety` 尝试减少整餐“同一家族被两道菜声明”的整数对数，每次严格下降，因而有终止上界。仅在规则分相等、各目标逐维不退步、角色一致、餐次不变差、查询相关性不下降、已覆盖食材偏好不丢、明确荤素/汤数及指定槽位保持的范围内交换。不是全局最优，不处理成菜主做法或跨餐轮换。安全候选必须由调用方先筛选，函数自身不是安全审查器。

`MenuPlanner.plan(..., experiment_menu_variety=False)` 默认关闭；服务/API未打开该参数。普通继续即使显式打开实验也不重排。目录标签不作为独立质量证明；未获得净收益证据前不启用正式回复。

| 证据 | 实测 | 不能推出什么 |

| 家族对数降低 | 5/10 | 不是主要食材去重成功或质量提升 |

新增咸肉蒸蛋、油渣白菜、小米蔬菜糕、小葱金针豆腐尚缺既有独立源角色审核，尤其不能用staple标签证明小米蔬菜糕适合五人共享主食。另一份6道含1汤也仍有南瓜重复。全食材重叠把配菜/配料与主体同权，有可能为了减少配料重复换掉更合理的成菜，这是下一轮需核对的失败机制，不由此猜测量化营养。

家族指标来自生产映射，只是算法诊断；另行读过的4份含南瓜源记录提供重复证据，未命中不代表没有南瓜。19份manifest文件已逐一验SHA。旧021534（按名审核有同名扩张风险）与021840中间报告保留；最终包改为冻结ID/指纹绑定，不能用旧包当作最终验收。
