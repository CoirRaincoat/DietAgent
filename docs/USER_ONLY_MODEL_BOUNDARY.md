## 默认数据流

DeepSeek.parse仅发送当前用户文本、最近6条用户历史、confirmed/pending字段类型、是否待过敏确认、是否已有菜单/待规划、菜单槽号、固定餐次/做法取舍选项和是否待口味确认。用正向白名单构造，不复制后删敏感字段。

不发送profile/raw/体检、归一化constraints/diners、档案ID或成员名称、菜谱ID/名称/原料/步骤、facts、助手/tool/system历史、生成的澄清原文或口味撤回原文。模型只抽本轮增量；完整状态/档案及Intent语义、人物归属、过敏/不辣/素食/数量/局部权限在本地核验。

用户自己输入的健康需求、人物称呼或菜名仍属于可发送的用户文本；这不是匿名/零健康信息协议。用户自行复制源内容到消息也不会自动识别并删掉。本地系统不会自动从档案/菜谱补这些文本。

DeepSeek.explain无HTTP，按本地facts顺序返回全部ID；服务本地渲染，`explanation_source=verified_template`，不误报解释失败。原方风险/未知程序等必保事实不删除。assistant历史本地保存，后续parse只取role=user且重建role/content两字段，不回传生成说明。

原档案仍标original；明确档案“不辣”本地种入独立禁辣标志，旧会话仅升级profile_owner。清淡/不太辣不推断成不辣，退出人物不自动影响本餐。缺可靠成分/品牌/用量/份数不承诺低钠/护心/足量。
